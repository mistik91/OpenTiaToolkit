# S7DCL Data Authoring

1. Read [data-blocks.md](references/data-blocks.md), [layout-catalog.md](references/layout-catalog.md), and the shared [format contract](../plc-code-engineering/references/format-contract.md).
   Use `assets/Codex_Data_Probe.s7dcl` for a minimal DB and `assets/Codex_Data_Struct_Probe.s7dcl` for nested structures, strings, arrays, and start values.
2. Run `discover-plc-code-capabilities` for the exact DB and continue here only when it selects `DirectDocuments`; use VCI when selected and stop on `Blocked`. Inspect the DB, UDT dependencies, cross-references, HMI bindings, and optimized-access requirement.
3. Export before modification and retain the exact untouched S7DCL/S7RES pair in a separate directory. Preserve unrequested members, order, attributes, number, retain settings, and start values. A changed interface or initialization is not interchangeable with an implementation-only request.
4. Write UTF-8-with-BOM `.s7dcl`. `.s7res` is optional unless `MLC_*` is referenced.
5. Run both `validate-plc-code-artifact --code-format=s7dcl` and `validate-plc-documents`. Stop for duplicate members or start assignments, invalid array/string bounds, unbalanced structures, invalid Bool values, instance-DB markers, or missing resource text. Resolve every project-type warning before apply; do not infer that a similarly named UDT exists in the target group. Qualify an unknown layout only with a uniquely named missing DB through `run-plc-code-probe`, then require an exact `query-plc-code-evidence` match for the intended artifact and current compatibility fingerprint.
6. Use one persistent PLC code transaction even for an isolated DB: bind the discovery id at begin, add a new DB with `target-mode=create-only`, or modify an existing DB with `target-mode=baseline-bound`, the untouched `baseline-directory`, and the narrowest exact `allowed-changes` set. DB declarations are `Interface`; start assignments are `Implementation`; header flags are `Attributes`; S7RES text is `Resources`. Review the contract fingerprint and changed sections plus capability and impact fingerprints, exact identities/actions/hashes, layout change kinds, PLC consumers, unresolved HMI/recipe/OPC UA/communication/absolute-address scope, dependencies, execution order, and compile policy. Apply `Safe`; acknowledge the exact impact fingerprint for `ReviewRequired`; accept `Unknown` only after manual consumer review; stop on `Blocked`. For a DB plus UDT/caller change, discover and bind every target and use `depends-on` where the type relationship is not inferable from block calls.
7. Verify canonical read-back and compile. Recheck absolute-address, HMI, recipe, OPC UA, and communication consumers whenever layout, optimized access, retain behavior, or member order changes. If the DB is a disposable contract for runtime assertions, pair it with a disposable scheduler and route the complete package through `plc-behavior-verification`; never write production DB members as test stimuli.

Do not recreate instance DBs as global DB documents. Generate PLC types from validated SCL, patch existing types with baseline-bound SimaticML, or use a validated VCI mapping; do not treat a type as a block document.
