# PLC Code Engineering

1. Read [format-contract.md](references/format-contract.md) and [format-coverage.md](references/format-coverage.md). Establish the exact TIA project and PLC with `basic-tia-interaction`.
2. Inspect `get-software-tree`, `get-blocks`, `get-block-info`, and concrete cross-references before modifying an existing object.
3. Run `discover-plc-code-capabilities` for every exact intended target before generating code. Supply object kind/name/group, create or modify intent, block type/language when known, and whether source control is preferred. Review its TIA version, CPU family, target language/protection, safety context, VCI mapping/status/formats, observed export routes, ranked rejection reasons, and fingerprint. Stop on `Blocked`; never override an F-target, read-only target, or ambiguous name with a format guess.
4. Follow `SelectedRoute`: VCI uses `vci-sync-workflow` and is not a direct-import transaction; `DirectDocuments` routes to the S7DCL skills; `DirectScl` routes to `scl-source-authoring`; `SimaticML` routes to `simaticml-plc-fallback`. `describe-plc-code-formats` explains authoring coverage but does not replace live capability evidence.
5. Prefer a new uniquely named block for generated logic. Connect it to existing code only after it compiles. When validation returns `unknown-requires-live-probe`, create missing-target `Create` capabilities for a uniquely named SCL or S7DCL probe and run `run-plc-code-probe --confirm=true`. The runner must import through the normal transaction, compile, canonically export, remove every exact block/type/source, recompile, and prove absence before it records `Verified`. Treat `Quarantined` as a cleanup incident. Never use an existing production object as the probe.
6. Before relying on prior live qualification, run `query-plc-code-evidence` with fresh intended-target capabilities and the production artifact. Accept promotion only when it returns an exact `Verified` evidence id for the normalized construct signature and compatibility fingerprint: TIA version/build, PLC identity, route/format, safety context, object shapes, and project fingerprint when external dependencies make the evidence project-bound. Start that change with `begin-promoted-plc-code-transaction`, supplying the exact evidence id, artifact path, capability ids, and explicit `save-decision` plus `source-control-decision`. The binding is revalidated at plan and apply; artifact drift, validator changes, evidence without cleanup proof, compatibility drift, extra operations, or a different source path fail closed. `ManualAfterVerification` and `VCISeparateAfterSave` record required follow-up; direct import never silently saves or impersonates a VCI synchronization. When runtime behavior rather than import/compile qualification is required, route to `plc-behavior-verification`; its evidence additionally binds the vector and PLCSIM fingerprint. `Failed`, `Running`, and `Quarantined` records never promote support. A miss leaves the offline classification unchanged.
7. For direct-import changes that do not depend on reusable qualification evidence, bind discovery ids in `begin-plc-code-transaction`. For an atomic multi-target change, discover every target first and pass all ids with `--capability-ids=<id1,id2,...>`. The engine re-observes every fingerprint at begin, plan, and apply and rejects stale target, TIA, project, PLC, language, protection, safety, VCI, or route evidence. Add new S7DCL objects with `target-mode=create-only`. Modify an existing S7DCL object only from its untouched export with `target-mode=baseline-bound`, `baseline-directory`, and the narrowest exact `allowed-changes` set (`Attributes`, `Interface`, `Implementation`, `Resources`). Identity changes are never part of this contract. The engine persists and rechecks the baseline hash, candidate hash, semantic-section delta, and contract fingerprint at plan and apply. Then add the complete operation set and plan once. Planning infers dependencies, resolves external calls, compares interface/layout signatures, reads PLC consumers when required, and returns `Safe`, `ReviewRequired`, `Unknown`, or `Blocked`. Apply a `Safe` plan directly. For `ImpactReviewRequired`, read `get-plc-code-impact` and acknowledge the exact fingerprint with `approve-plc-code-impact`; set `accept-unknown=true` only after explicitly reviewing incomplete evidence. Never approve `Blocked`. Use `depends-on=<sequence,...>` for dependencies that cannot be inferred; reject cycles instead of guessing.
8. Never replace a multi-object intent with sequential single-block applies. The older `plan-block-document-import` token is process-local and is suitable only when plan and apply are guaranteed to share one persistent host session.
9. Treat `Stale` as a mandatory replan. Treat `RecoveryRequired` or probe evidence `Quarantined` as an incident: retain the package and use `recover-plc-code-transaction --confirm=true`; never discard it before all hashes and the rollback compile are proven.
10. For native SCL sources, run `validate-plc-code-artifact --code-format=scl`. Use `add-scl-source-transaction-operation` for atomic generated block/type changes and set `type-group-path` when TYPE declarations do not belong at the root. SCL generation is not a lossless export-edit route: do not replace an existing object from generated SCL unless its authoritative source is already controlled and the selected route proves that workflow. Otherwise use baseline-bound S7DCL, SimaticML, or VCI. Delete a PLC type only through `add-delete-plc-type-transaction-operation`, which snapshots XML and verifies absence/rollback.
11. Verify the exact block and compile. Do not save on compile errors. Save only when the user wants the verified change persisted.

Do not assume every block supports every format. Do not hand-author general FlgNet XML when S7DCL can represent the LAD. Treat safety blocks separately; standard LAD in an F-CPU project does not imply F-block generation support.
