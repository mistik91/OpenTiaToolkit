# PLC Code Engineering

1. Read [format-contract.md](references/format-contract.md) and [format-coverage.md](references/format-coverage.md). Establish the exact TIA project and PLC with `basic-tia-interaction`.
2. Inspect `get-software-tree`, `get-blocks`, `get-block-info`, and concrete cross-references before modifying an existing object.
3. Run `discover-plc-code-capabilities` for every exact intended target before generating code. Supply object kind/name/group, create or modify intent, block type/language when known, and whether source control is preferred. Review its TIA version, CPU family, target language/protection, safety context, VCI mapping/status/formats, observed export routes, ranked rejection reasons, and fingerprint. Stop on `Blocked`; never override an F-target, read-only target, or ambiguous name with a format guess.
4. Follow `SelectedRoute`: VCI uses `vci-sync-workflow` and is not a direct-import transaction; `DirectDocuments` routes to the S7DCL skills; `DirectScl` routes to `scl-source-authoring`; `SimaticML` routes to `simaticml-plc-fallback`. `describe-plc-code-formats` explains authoring coverage but does not replace live capability evidence.
5. Prefer a new uniquely named block for generated logic. Connect it to existing code only after it compiles.
6. For every direct-import change, bind the discovery id in `begin-plc-code-transaction --capability-id=<id>`. For an atomic multi-target change, discover every target first and pass all ids with `--capability-ids=<id1,id2,...>`. The engine re-observes every fingerprint at begin, plan, and apply and rejects stale target, TIA, project, PLC, language, protection, safety, VCI, or route evidence. Then add the complete operation set and plan once. Planning infers dependencies, resolves external calls, compares interface/layout signatures, reads PLC consumers when required, and returns `Safe`, `ReviewRequired`, `Unknown`, or `Blocked`. Apply a `Safe` plan directly. For `ImpactReviewRequired`, read `get-plc-code-impact` and acknowledge the exact fingerprint with `approve-plc-code-impact`; set `accept-unknown=true` only after explicitly reviewing incomplete evidence. Never approve `Blocked`. Use `depends-on=<sequence,...>` for dependencies that cannot be inferred; reject cycles instead of guessing.
7. Never replace a multi-object intent with sequential single-block applies. The older `plan-block-document-import` token is process-local and is suitable only when plan and apply are guaranteed to share one persistent host session.
8. Treat `Stale` as a mandatory replan. Treat `RecoveryRequired` as an incident: retain the package and use `recover-plc-code-transaction --confirm=true`; never discard it before all hashes and the rollback compile are proven.
9. For native SCL sources, run `validate-plc-code-artifact --code-format=scl`. Use `add-scl-source-transaction-operation` for atomic generated block/type changes and set `type-group-path` when TYPE declarations do not belong at the root. Delete a PLC type only through `add-delete-plc-type-transaction-operation`, which snapshots XML and verifies absence/rollback.
10. Verify the exact block and compile. Do not save on compile errors. Save only when the user wants the verified change persisted.

Do not assume every block supports every format. Do not hand-author general FlgNet XML when S7DCL can represent the LAD. Treat safety blocks separately; standard LAD in an F-CPU project does not imply F-block generation support.
